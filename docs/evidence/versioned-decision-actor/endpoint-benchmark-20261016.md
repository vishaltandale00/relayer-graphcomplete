# Judge-gated endpoint benchmark revision

The user explicitly requested explaining the unfinished Decisions stop, correcting the comparison stopping policy, and rerunning both implementations to the same endpoint. PRD §13.2.3 records that new benchmark decision. Ordinary participant behavior and all historical source/run receipts remain immutable.

## Diagnosis

The preceding hybrid used behavior v7 with `participantMayStopIncomplete: true`. It proposed `satisfied`, `endpointStatus: incomplete`, and named the missing rollback trigger. The judge returned incomplete with a valid continuation hint. The host and task finish module deliberately admitted this voluntary stop; no response/action/time budget forced it (3/4 responses, 7/60 actions). The new actual-service red regression recorded just one incomplete/uncertain verdict and no recovery. It is a policy mismatch for an endpoint benchmark, rather than a lost judge result or faulty Decisions API response.
