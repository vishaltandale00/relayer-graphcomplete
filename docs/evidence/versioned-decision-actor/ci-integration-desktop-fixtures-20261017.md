# MCI-007: desktop fixture model-family contract

The first declared `test:desktop:node-input-actions` run failed before candidate execution: its new custom family omitted the explicit orchestrator required by main's ADR 0006/model-family-roles contract. `desktop-node-inputs.log` remains an actual failed run. This is a producer-fixture correction, not a relaxation of family admission.

Four declared desktop fixtures create custom families: node-input actions, interaction-context lifecycle, project-new-thread, and artifact-viewer. Each singleton member now explicitly carries `roles: [{ name: "orchestrator" }]`. Node-input/context thread requests supply only the selected `familyId`, matching the new producer contract instead of requesting a per-model override. The node-input response-loss assertion checks exact JSON equality to that selected family; the later-generation replay checks exact equality to the original request. Existing text, input-generation, annotation provenance, admission, response-loss and replay assertions remain. The interaction-context picker proof also moves from the retired per-model radio to the selected family and its visible orchestrator card, retaining the click-to-close and trigger-focus assertions. The first migrated context run failed on that obsolete selector and remains recorded. The visual-node-details fixture uses configuration-owned Eval execution and creates no custom family.
