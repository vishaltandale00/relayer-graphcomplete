# Experimental Codex instruction graph

The user approved an Eval-only `codex-instruction-graph-v1` comparison on 2026-10-19 and selected a $10 declared cap. The ordinary two-turn preset runs four roots, with model-controlled children authorized by the dashboard confirmation. This declaration is not a provider spend meter. No default harness was promoted.

Generic manuals are published as ten digest-verified accepted graph modules using the existing graph engine. A compact bootstrap supplies task context, sealed contracts, V6 preferences and scoped retrieval. Model, reasoning, permissions, graph capabilities and provider-native recursion match the current control. GraphComplete retains acceptance and scope authority; no scheduler was added.

## Preserved failures and recovery

The first global check selected a stale graph-core artifact from another worktree sharing Cargo output. Verification moved to a private target. The first isolated check exposed an exact migration fixture list missing migration 42; its assertion was retained and repaired. The real-engine search fixture then requested the intentionally hidden `id` property, followed by an incorrect 400 expectation for target refusal. It now checks the exact pinned title/detail row and the existing 422/`invalid_request` contract; focused and full search proofs passed.

The runtime journey initially timed out on first server readiness; one unchanged retry passed all three scenarios. Its final full-suite receipt passed too. No assertion or timeout was weakened.

An old Ladybug cache was rejected for a Cargo.lock mismatch. The locked source build reused warm compiler output, and the repository artifact workflow created and verified a new bundle, including source identity, library hash and inventory. Cached artifacts accelerated the private builds and never replaced tests.

The embedded browser could not show the budget prompt, and the Mac was initially locked. After the user confirmed unlock on 2026-10-20, Safari completed the ordinary budget and four-root/child confirmation. First run `run-2026-10-20T13-12-15-499Z-ef6f3d89` accepted its two baseline turns but correctly refused the new treatment pending independent readiness. Settings provider Refresh made the treatment ready; a later unrelated configuration caused the generic refresh error. No catalog-policy bypass or database mutation was used.

That run exposed a metrics-reader defect: the real exporter writes `manifest.truncation: null` and omits `descriptor.truncated` unless true. The reader had required a nonexistent `manifest.truncated: false`. A production-export regression reproduced the failure before repair. Hash/count/trace/interaction/correlation checks remain intact, and truncated or corrupt evidence stays unknown. A missing `readFile` import in the new test was fixed before the passing rerun. Earlier failed logs remain under `.relayer/instruction-graph-v1/`.

## Retrieval and input-usage inspection

[Trace analysis](trace-analysis.json) binds the original bundle and all four trace/ledger artifacts by hash. Its per-request input counters sum exactly to each final cumulative receipt. [Instruction corpus](instruction-corpus.json) contains the exact generic module bodies, node IDs and read counts; its digest matches the live pin. Provider-native base instructions are outside that corpus.

The control recorded 12 input-bearing model requests; treatment recorded 19. Initial native request input fell from about 31.1k to 17.8k tokens, less than the 82% custom-prompt character reduction because the native context remains. Treatment later reached 43.4k and 46.5k input tokens per request, compared with control maxima of 39.6k and 40.1k. Input usage sums requests, including cached history; it is not peak context occupancy. Average input per recorded request actually fell from about 36,214 to 34,837 tokens. Request count rose 58%, so aggregate input still rose 52%. Uncached input also rose, from 56,963 to 77,190 tokens.

Successful reads printed 210,634 instruction-body characters across both turns. Six within-turn rereads account for 83,403 of those characters. Batches printed roughly 51k and 56.5k characters before the smaller follow-up fetches. The export contains no explicit truncation marker, and recorded reasoning summary/content fields are empty. Oversized-output recovery or checking details is plausible, but the reason for those six rereads is not recorded and must not be presented as established fact. Read-once behavior is prompt guidance rather than enforced retrieval deduplication.
