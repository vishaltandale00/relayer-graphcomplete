# Interaction context evidence

This evidence slice extends the existing real-Electron lifecycle and capture scripts for two occurrence-bound drafts across service and BrowserWindow restart, then confirm/discard, fresh-draft warning, Go back, explicit override, and historical restoration. It does not change product behavior or product wording.

| Checkpoint | Executable seam | Required observation |
| --- | --- | --- |
| Both complete draft records retain IDs, target occurrences, revisions, and text over restart; selecting either node restores its editor | Existing `scripts/test-interaction-context-lifecycle.mjs` and capture journey | Structural equality against the durable API records before and after restart |
| Confirming A preserves the entire B draft; discarding B preserves the complete A confirmation | Same existing runner and capture journey | Structural equality at both authority boundaries |
| Warning and Go back preserve the entire fresh B draft and add no interaction | Same existing runner and capture journey | Complete draft comparison and interaction-ID equality |
| Explicit override submits exactly A's occurrence with its single annotation; B remains durable and restores at its source history occurrence | Same existing runner and capture journey | Exact canonical submitted context payload and full post-send draft comparison |

Product meaning comes from PRD §7.1 and the node-input layout clarification. Graph occurrence authority remains governed by ADR 0007 and the production draft API. The existing direct-send, confirmation-race, persistence, and keyboard/focus warning boundaries remain in their current runners; this repair adds no parallel test and removes no test.

The repair plan requires two continuous recordings directly sampled from the real Electron `BrowserWindow`: one from opening and saving A through switching/saving B and restoring both before restart, and one after restart through restoration, confirm/discard, fresh draft, both warning decisions, override, and final historical restoration. The services and window necessarily stop between those recordings. The new manifest must preserve both segments, real frame/event timestamps, and an explicit restart discontinuity; it must not present a still montage or fabricated/interpolated frames as continuous proof.
