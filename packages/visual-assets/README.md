# Visual assets

`@relayer/visual-assets` is the deterministic library/tool seam for logical visual assets. Callers discover registries, root tags, one tag layer, and scoped assets through the `VisualAssetsLibrary` interface. They add only harness-provided file handles and receive logical asset objects; generic content records and digest deduplication remain private to the Module.

Project queries include project-associated assets plus assets associated with authorized project threads. A query narrowed to a project-attached thread includes project assets and that thread's assets. Those threads share the project tag tree; projectless threads own separate tag trees.

Asset bytes are immutable in v1. Organization and scope associations may change, and archival removes user assets from ordinary discovery without invalidating their accepted digest references. Public downloads resolve one logical `assetId`; digest-only lookup remains an internal persistence concern. System registries can keep content and default relationships read-only while allowing user-created associations and tag relationships.

V1 supports JPEG, PNG, and SVG. `add` immediately copies bytes returned by the harness, then uses only that owned snapshot for digesting, validation, indexing, inspection, and download. PNG/JPEG structure parsing identifies the actual terminal boundary before Sharp fully decodes the representation; fake terminal records and trailing bytes are rejected. Raster validation caps encoded bytes, decoded pixels, decoded bytes, and concurrent validations with explicit errors. SVG is fully parsed with the maintained strict SAX parser and a fail-closed element, attribute, reference, and narrowly parsed presentation-value grammar, including rejection of escaped resource schemes. AVIF, GIF, and WebP are rejected as unsupported in V1 rather than accepted from header probes. `inspect` resolves, validates, and digest-verifies content before returning a frozen file-backed preview; unavailable or corrupt content fails explicitly.

Every public async operation snapshots its complete input synchronously before its first suspension. Discovery uses locale-independent UTF-16 code-unit order with ID as the final tie-break. A continuation cursor is bound to its explicit query scope, canonical tag context, sort, and the library revision at which its page was issued. If addition, archival, association, or tag reorganization changes the inventory before the next page, continuation fails with `page_snapshot_stale`; callers restart the query instead of receiving a page that may duplicate or skip entries. An operation that leaves observable inventory unchanged does not advance the revision or stale a cursor.

Bootstrap tags are normalized and validated as one set before parent resolution, so valid child-before-parent input is accepted while missing parents, cross-scope parents, blank names, and cycles fail atomically. `initialAssets` is a validated bootstrap/catalog seam for deterministic fixtures and process reopen handoff, not durable persistence. Every initial asset must provide bytes and passes the same media, length, and digest checks before any initial asset is published. Callers can explicitly carry provenance and archived state across that seam. Durable persistence remains separate work.

Accepted Node Details use the separate `VisualDetailPersistence` interface. Acceptance verifies a canonical compiled package against authorized logical assets, snapshots useful provenance, and copies digest-addressed bytes into accepted storage before catalog metadata can change. Read, resolve, and export require the owning scope and reject caller-forged detail handles. `createFileVisualDetailPersistence` stages mutations in an isolated candidate and atomically publishes them only after an owner-only durable rename succeeds; its durable store retains each detail's scope across reopen. Export serializes each reachable digest once even when several logical assets or placements share it; import snapshots caller data synchronously and verifies package, content, media, reachability, and scope before publishing any accepted detail. These product-facing operations never expose a generic content-store identifier or add persistence operations to the agent-facing `VisualAssetsLibrary` interface.
